# 6502 CPU Implementation in C++

This project is a small implementation of the MOS 6502 processor. It can read a
6502 assembly program from a text file, assemble and load it into memory, then
decode the generated bytes through a 256-entry opcode table and execute them.

The repository started as a fork of
[Mir-Aatif-Rafiq/NES-Emulator-in-Cpp](https://github.com/Mir-Aatif-Rafiq/NES-Emulator-in-Cpp).
My work on the fork is focused only on completing and testing the standalone
6502 CPU. It is not an NES emulator.

## What is implemented

- Accumulator, X and Y registers
- Program counter, stack pointer and processor status register
- 64 KB byte-addressable memory connected through a bus
- The addressing modes used by the official instruction set
- A 256-entry opcode lookup table
- Arithmetic, logic, load/store, branch, transfer and stack instructions
- Binary and packed-BCD arithmetic for `ADC` and `SBC`
- Reset, IRQ, NMI, BRK and RTI behaviour
- Instruction cycle counting, including branch and page-crossing penalties
- A two-pass text parser with labels and automatic addressing-mode selection
- Automatic program loading, reset-vector setup and bounded execution

Unofficial opcodes are currently treated as either `NOP` or an unsupported
instruction. The implementation tracks instruction cycle counts, but it does
not try to reproduce every bus action on every individual clock edge.

## Build and run

The project only needs a C++17 compiler and `make`.

```bash
git clone https://github.com/diaznakh/NES-Emulator-in-Cpp.git
cd NES-Emulator-in-Cpp
git checkout CPU
make run
```

The default example executes:

```asm
LDA #$05
CLC
ADC #$03
STA $0200
```

Expected output:

```text
Loaded: examples/add_and_store.asm
Stopped: end of program
Instructions: 4
Cycles (including reset): 17
PC: $8008
A: $08  X: $00  Y: $00
```

To execute another assembly text file:

```bash
make run PROGRAM=examples/countdown.asm
```

You can also build once and pass a file directly:

```bash
make cpu_demo
./cpu_demo path/to/program.asm
```

## Assembly text format

The parser accepts one instruction per line. Mnemonics and labels are not case
sensitive, and a semicolon starts a comment. It is a deliberately small project
assembler rather than a replacement for a production 6502 assembler. It
supports the addressing syntax already represented by the CPU's official
opcode table:

```asm
.ORG $8000       ; optional, defaults to $8000
LDA #$05         ; immediate
STA $10          ; zero page
LDA $1234,X      ; absolute indexed
LDA ($20),Y      ; indirect indexed

loop:
DEX              ; implied
BNE loop         ; signed relative label
.BYTE $EA, 234   ; place literal bytes in memory
.END             ; optional executor stop marker
```

Numbers may use hexadecimal (`$2A` or `0x2A`), binary (`%00101010`) or decimal
(`42`) notation. The assembler makes two passes: the first records labels and
instruction addresses, and the second resolves operands and emits opcode bytes.
It chooses zero-page or absolute opcodes from the operand value and uses the
CPU's existing 256-entry table as the source of truth.

`.END` does not become a byte in memory. End-of-file has the same effect. This
keeps termination outside the emulated processor because `BRK` is a real 6502
software interrupt, not a halt instruction. The executor also has a maximum
instruction count so a program containing an infinite loop returns control to
the host application.

## Tests

```bash
make test
```

The CPU tests cover reset state, memory boundaries, arithmetic and flags, BCD
arithmetic, relative branches, subroutines, stack behaviour, register transfers,
BRK and RTI. Separate executor tests cover stream and file parsing, labels,
addressing-mode selection, invalid input and the infinite-loop guard.

## Files

- `cpu.h` contains the CPU state, opcode table, RAM and bus interfaces.
- `cpu.cpp` contains the addressing modes and instruction behaviour.
- `executor.h` and `executor.cpp` contain the assembler, loader and run loop.
- `main.cpp` accepts an assembly text-file path and prints the final CPU state.
- `examples/` contains runnable 6502 assembly text files.
- `tests/test_cpu.cpp` contains the instruction-level tests.
- `tests/test_executor.cpp` contains parser, loader and run-loop tests.
- `Notes.txt` contains the original learning and design notes from the project.

## Current scope

The goal here is to understand and implement the processor itself. Cartridge
loading, graphics, audio and other NES hardware are intentionally outside the
scope of this fork.
